# 旅行攻略 HTML 使用指南

`travel-guide-html` 将可执行的旅行计划整理成单个 HTML 文件，优先保证攻略内容、手机阅读与交通衔接。适合需要可保存、可直接打开的网页攻略的人；普通旅行咨询、纯文字行程、单项景点或酒店推荐，以及一般网站开发不触发。

安装方法见[项目 README](../README.md)。执行规则以 [SKILL.md](../travel-guide-html/SKILL.md) 为准；本页介绍如何提出需求、理解交付结果及维护模板。

## 选择入口

| 需求 | 处理方式 |
|---|---|
| 从零规划并生成 HTML | 整理约束、核验动态信息、完成路线，再制作文件 |
| 已有行程转 HTML | 保留景点、顺序、已订交通和住宿，检查冲突并补充实用攻略 |
| 修改已有攻略 HTML | 提供现有文件与修改要求，按同一套内容和交付标准调整 |

已有安排存在冲突时，涉及已订交通、住宿等硬约束的调整会先说明并询问；其他整理工作可继续。

```text
使用 $travel-guide-html 规划 3 天杭州旅行，并生成手机阅读舒适的单文件 HTML 攻略。
日期为 2026 年 11 月 6 日至 8 日，2 名成人，杭州东站往返；暂未订交通和住宿。
重点是西湖、历史街区和本地美食，节奏适中，不安排地图。
```

```text
使用 $travel-guide-html 将附件中的已定行程整理成 HTML。
保留已订交通、酒店和景点顺序，补充景点玩法、美食、交通衔接及备用方案。
```

修改时可直接说：“使用 $travel-guide-html 修改这个 HTML，把第二天改为雨天方案，并同步总览、预算和准备清单。”

## 提供哪些信息

新规划必须明确目的地和可用天数；其他信息尽量一次提供，已有上下文无需重复。

| 信息 | 用途与缺失时的处理 |
|---|---|
| 出发地、抵离时间与站点 | 安排往返交通及首尾衔接；只处理目的地内行程时可省略出发地 |
| 日期 | 核验票务、闭馆与季节条件；日期未定可做通用方案并标明待确认项 |
| 人数与成人儿童构成 | 统一预算、房间与点餐口径；未知时按人均或每间计价，不默认两人 |
| 已订交通、住宿、预约 | 作为硬约束；未订时给建议时间窗，不虚构固定班次 |
| 必去／可去／不去、预算与偏好 | 确定优先级、强度与住宿区域，未知时说明合理假设 |
| 体力、老人儿童、无障碍、行李及忌口 | 避免路线和用餐安排与实际限制冲突 |

以多日旅行为主，也可以将已有一日行程整理成 HTML。资料不全时会集中补问真正影响规划的信息。

## 会得到什么

通常包括总览、每日页面与准备清单；特产等模块按适用性出现，不为填满模板保留空栏目。

- **总览**：解释为什么这样走，汇总每日核心安排、往返交通、住宿区域、预算与核验来源。
- **每日攻略**：主题与 Dashboard、真实占用时间的交通和餐次、时间轴、可展开的景点看点与玩法。
- **实际衔接**：住宿区域的地理理由、行李安排、返程余量、排队或天气变化的替代动作，以及可选顺路项。
- **按需补充**：路线内美食、购买地点与理由明确的伴手礼，以及预订、证件、装备和出发前复核清单。

页面采用暖纸质底色、细线层次、克制矿物分类色与响应式排版。重要时间、交通与预约限制直接显示，详细玩法可展开；总览、Dashboard 和预算应来自同一份最终行程。

摄影按需增强：普通攻略可有一句拍照提示；明确提出摄影需求后，才在地点详情内补充机位、光线、时间与拍法。手机优先，专业器材建议按需提供。若摄影是主要目的，请在规划开始时说明，以便把拍摄窗口纳入约束。

## 联网、文件与使用边界

- **生成阶段需要联网核验**：优先官方运营方及具体场所信息；关键结论保留来源、查询日期和状态，区分已确认、已核验、估算与待确认。
- **交付为一个 HTML**：核心 CSS、JS 与正文内联，无地图、无坐标依赖，无需服务器、构建命令或配套代码文件。
- **不保证完全离线**：允许按需使用有来源的在线图片与资料链接；使用在线资源时会说明联网需求，资源失效应仍能阅读正文。
- **正文优先可读**：保留原生锚点和折叠，JS 禁用或增强失败时仍有完整内容；单文件不等于所有手机内置预览器都支持脚本。

下载后用浏览器打开。手机文件管理器能否交给浏览器、内置预览器的交互支持情况，以实际验证为准。出行前仍需复核会变化的预约、交通与营业信息；无法核验的关键限制应明确影响及替代安排。

## 维护模板与验收

普通用户生成攻略无需安装测试框架。维护者修改模板交互或抽检已生成的攻略 HTML 时，可从仓库根目录运行：

```powershell
node .\travel-guide-html\scripts\check-template.cjs
# 或校验指定生成的攻略文件：
node .\travel-guide-html\scripts\check-template.cjs .\path\to\guide.html
```

该脚本需要现有 Node、能被脚本解析的 `playwright` 包及可启动的浏览器。仓库没有独立的 Node 安装清单，也没有 `npm test` 命令。

| 环境变量 | 用途 |
|---|---|
| `GUIDE_ENGINE` | 默认 `chromium`；设为 `webkit` 可使用已有的 Playwright WebKit 环境 |
| `GUIDE_BROWSER` | 可指定本机 Chromium 浏览器可执行文件的绝对路径；不指定时使用所选引擎的默认浏览器 |

切换 WebKit 时不要沿用 Chromium 的可执行文件路径；需要已有对应浏览器。例如，在当前 PowerShell 中选择 WebKit：

```powershell
$env:GUIDE_ENGINE = 'webkit'
$env:GUIDE_BROWSER = $null
node .\travel-guide-html\scripts\check-template.cjs
$env:GUIDE_ENGINE = $null
```

[检查脚本](../travel-guide-html/scripts/check-template.cjs)默认读取模板，构造多日和移除可选页的临时样本，检查本地打开、五档宽度、长内容、导航与总览入口、跳过导航、锚点、键盘折叠、打印全页显示、文字放大及脚本失败降级；传入攻略 HTML 路径时，还会额外检查无残留占位符、链接协议安全与图片替代文字。

脚本通过不能证明旅行事实正确，也不能代替最终文件的内容、真实手机或 Safari 检查。最终攻略应按 [Skill 完成标准](../travel-guide-html/SKILL.md#完成标准)验收，未实测的平台如实说明。维护内容和布局时分别参阅[内容与字段约定](../travel-guide-html/references/data-model.md)及[页面与实现规范](../travel-guide-html/references/layout-spec.md)。
