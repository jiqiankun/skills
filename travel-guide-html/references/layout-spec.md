# 页面与实现规范

## 信息架构

顺序为顶部旅行标题 → 吸顶导航 → 总览／Day 1…N／特产（适用时）／准备清单；各页底部提供纯锚点翻页条（`.pager`）便于手机单手切换上下日或返回总览。默认总览，日期可直接定位；总览按“封面图（可选）→ 路线逻辑 → 优先确认（有硬约束时）→ 每日核心索引（多日）→ 往返／费用／住宿 → 信息核验来源”排布，一日游可省略“每日核心”多日索引。

每日先显示主题、Dashboard、今日提醒和当晚／返程衔接，再显示时间轴与适用备用方案。时间轴节点按“如何到达（前站→本站入口）→ 核心体验 → 门票／限制 → 详情折叠 → 离场衔接（出口与最晚离开时间）”组织，去下一站的具体交通写在下一张卡的“如何到达”中，避免前后重复。景点详情使用一级原生 details/summary；不为主要内容增加嵌套折叠。来源集中在总览并用 `.status` 标注状态，重要的开放与预约限制必须在相关卡片直显。

| 直显 | 折叠或次级 |
|---|---|
| 时间、地点、如何到达、价值摘要、关键门票／预约、离场与最晚离开、当日重点提醒 | 景点详细顺序、内部路线、背景细节、避坑、少量附近推荐（`.optional`）、按需摄影 |
| 正餐安排、排队替换条件、住宿／返程衔接 | 详细点法、区域比较、低频便民信息 |

可选内容缺失时删除对应元素；特产整页删除时同时移除导航与页底 `.pager` 对应链接。不显示空标签或“无内容”的折叠。模板只保留一个 Day 骨架，按实际天数复制并同步导航、标题 ID、总览入口与页底翻页；不附带固定目的地示例。

## 视觉与移动端

- 使用模板中的暖纸底（`--bg`）、微高阶纸面（`--surface`）、深墨正文（`--ink`）、1px 细边界与零常驻阴影的扁平出版风层次；允许按目的地微调顶部纸面色与主强调色变量（`--hero-bg`、`--accent`、`--accent-hover`、`--accent-soft`），保持暖浅底深字高对比，不使用紫罗兰／薰衣草色调、多色渐变或毛玻璃模糊。分类标签统一映射：`.tag.scenic`（景点／自然松青）、`.tag.culture`（博物馆／古建／街区暖铜赭）、`.tag.food`（正餐／小吃／茶咖陶土红）、`.tag.transit`（交通接驳岩板灰）、默认 `.tag`（住宿／休息／购物／特产暖石），时间轴细轨与圆点自动呼应分类色，标签始终保留文字。硬性预约／截止／闭馆提醒用 `.note.warn`，普通建议用 `.note`。
- 标题采用衬线编辑体与无衬线正文的克制配对，靠字号与收紧字距拉开层级，不堆砌粗黑大块；正文16px、行高1.75，辅助文字与状态标签不小于14px，不要把主要攻略缩成小字。标题自然换行，正文左对齐；不强求所有区块居中。
- 页面主体最大宽度1032px，顶部刊头、吸顶导航、正文与页脚严格共享同一左右对齐边界；窄屏正文单栏，宽屏详情、总览卡片与特产列表（`.grid`）可两列。Dashboard 将短指标放 2 列（宽屏 4 列），文字较长的“主要交通”“天气与穿衣”使用 `.wide` 在窄屏占整行、宽屏跨 2 列，避免 360px 窄列挤压；数字与时间启用等宽数字（`tabular-nums`）。网格使用 minmax(0, 1fr)，跨全行用 grid-column: 1 / -1，避免隐式列。
- 360～430px 优先；手机卡片 20px 内边距（桌面放宽至 26–30px）、16–24px 间距；统一克制圆角体系（4 / 6 / 8px）。时间与类别一行可换行，长地点名称另起一行。长地址、链接与标签可断行，不以隐藏横向溢出掩盖内容裁切。
- 导航采用不透明底色加 1px 底线，与正文左缘对齐，窄屏允许单行横向滚动，其他正文不横向滚动；选中态以深墨字配 2px 底部实线标示，不使用发光胶囊或毛玻璃。微交互仅在精细指针下生效（列表箭头轻移、翻页按钮轻抬与按压、配图框内微缩放、正文链接细线展开），顶部刊头仅首次载入轻微入场，不随滚动淡入卡片。链接、翻页按钮和展开入口至少44px高，焦点即时可见；提供跳过导航入口（在任意日期页触发不重置回总览）。锚点定位留出吸顶导航高度，展开不设固定高度上限，并支持 `prefers-reduced-motion` 与 `@media print`（打印／导出 PDF 时显示全部页面并展开折叠）。
- 不用宽表格承载手机正文，不使用绝对定位徽章、大量渐变、无数据含义的图表或复杂动画。装饰与颜色不承担唯一的信息表达。
- 顶部建立目的地标题、标签化旅行摘要和核心体验的清晰层级；正文使用节奏一致的留白、分隔和小面积类别色。总览先解释路线逻辑与优先确认项，再给带清晰分隔的每日索引；每日强调主题与关键时间，详情中放丰富的玩法。内容卡片避免每条信息再套一个小卡片。
- 有经当次核验、可稳定访问的真实目的地图片时，可在总览加入一张 `.cover` 封面图，或在核心景点卡加入少量 `.spot-photo` 实拍图，配标题／说明；禁止凭记忆拼接 URL 或以无关图库图片冒充目的地，不要求每卡有图。设定宽高或宽高比、适当压缩、附 `referrerpolicy="no-referrer"` 与 `decoding="async"`，非首屏图片 `loading="lazy"`，图片不可用时保持替代文字可读且不遮挡正文。
- 摄影仅在地点详情内作为次级段落（如 `<div><h4>拍照参考</h4>...</div>`），使用同一套细节样式，无额外主题配色和日级摄影界面；启用条件遵守主说明。

## 静态正文与渐进增强

- 从 assets/guide-template.html 改写，全部攻略直接存在于 HTML；不得将正文留空再依靠 JS 生成，也不维护重复的 OVERVIEW／DAYS 等运行时数据。
- 保留原生锚点导航及 details/summary。少量内联 JS 仅增强为单页显示，使用 hash 支持直达与前进后退；切页不重建正文、不丢失折叠状态，焦点与标题一起定位。
- HTML 初始不隐藏任何正文；JS 禁用、语法错误或增强失败时退回完整文档。不要用 noscript 中的一句提示替代攻略正文。
- 页面 ID 使用 overview、day-1…day-N、souvenirs、prep；导航指向真实 ID。页面内的其他锚点也使用唯一 ID，JS 可切入目标所在页。
- 文本按 HTML 文本节点转义，属性值按属性上下文转义；不要将检索文本直接当 HTML 或拼入脚本。来源链接只允许 http/https，内部导航只用本文件锚点；不接受 javascript: 或事件属性。内容无需嵌入 JS。
- head 保留 UTF-8、viewport；默认系统字体。核心 CSS、JS 与正文内联，保证交付单个可直接打开的 HTML；允许按需使用 HTTPS 在线图片和资料链接，不再要求离线或零网络依赖。
- 视觉资源优先有意义的 CSS、内联 SVG 或真实目的地图片，Emoji 适量。字体、库或其他外部服务只有明确收益时才引入；不使用地图或追踪器，不默认使用 CDN、自动播放媒体或实时 API。无需 Service Worker、缓存框架或本地服务器。
- 控制图片尺寸与加载成本，在线资源不可用时保留文字与空间稳定性。代码按样式、正文、导航增强分区，注释使用中文；复杂度应服务阅读与内容展示。

## 检查方法

主说明维护完成标准，这里只规定页面检查方法：

1. 用本地 file:// 打开文件；若使用在线资源，核对 URL、来源、加载表现与失败时的替代显示。导航和攻略正文不依赖远程接口返回后才出现。
2. 逐页点击导航、总览每日入口与页底翻页，测试前进后退、直接带某日锚点打开、在某日页使用跳过导航（`#main`）、展开／收起、键盘 Enter／空格和焦点；可选模块移除后仍可导航且无悬空链接。
3. 在360、390、430px与桌面宽度检查全部展开、长标题／链接、文字放大和打印预览（`@media print` 全部页面可见）；正文无横向溢出或裁切，导航定位后标题可见。
4. 禁用 JS 重新加载，所有页面内容仍在，锚点和原生折叠可用；浏览器控制台不应有正常使用错误。
5. 维护模板或抽检生成的攻略 HTML 时可运行 `scripts/check-template.cjs`；使用现有 Node、Playwright 与可用浏览器，不将开发测试依赖放入最终 HTML。命令为 `node scripts/check-template.cjs`（默认测模板）或 `node scripts/check-template.cjs <待测攻略.html>`；`GUIDE_BROWSER` 可指定本机 Chromium 浏览器路径，`GUIDE_ENGINE` 可选 `webkit`（需已有对应浏览器）。未实测的平台如实记录。
